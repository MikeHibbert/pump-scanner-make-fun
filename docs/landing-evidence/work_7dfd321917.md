# Landing evidence — work_7dfd321917 (artifact gate: a blank dashboard cannot pass 7/7)

Declared deliverable for the parent item `work_7dfd321917` and its schema+tests child

## The failure this row exists to catch

On the token-radar-01 release of 25 Nov 2026 the artifact gate reported **7/7 green while the
dashboard painted nothing**. The cause was a temporal-dead-zone throw: `reviewHours` was a
`const` called by `farmSteps` inside the `rows.map`, so the page threw before first paint.
The only witness was a screenshot collapsing **347,462 → 105,432 bytes** — no row in the gate
ever executed the page. Recorded as Lesson 16 in `docs/kindling-training-lessons.md`.

## The row (schema half)

`tools/render-check.mjs` — the `renders` row. It:

1. requires `out/dashboard/index.html` and `out/board.json` to exist;
2. reads the expected row count from the board the program wrote
   (`Array.isArray(board.rows) ? board.rows.length : 0`);
3. spawns `tools/render-check.py` out of process (python3 + Playwright/Chromium), which opens
   the page over `file://`, lets the page's own scripts run unmodified, and reports
   `rows_painted`, `detail_label`, `detail_visible`, `empty_state_present`, `page_error`;
4. fails on any of: `page-error`, `row-count` (painted ≠ expected, compared for **equality**),
   `detail-label`, `empty-state` (placeholder shown while rows exist), and
   `empty-state-missing` (no rows and no placeholder);
5. fails closed with `render-unavailable` when the helper cannot launch — never a silent pass.

The out-of-process split is deliberate: this entry has no `node_modules`, so an in-process
Playwright import would throw at load and take every row down with it.

## The two rejected circular versions

Both were measured failing, and both are cheap to reintroduce by accident:

- **(a) no expectation at all** — "at least one row painted". A blank dashboard satisfies it.
- **(b) the expectation read back out of `out/board.json`** — only proves the JSON parses, and
  cannot fail in the direction that matters when the page and the JSON disagree.

The corrected oracle is the board the program wrote, compared for equality against the DOM row
count the page actually painted, plus a `--board` injection path that proves the row can fail
when the board is empty.

## The tests half

`tests/render-gate.test.mjs`, run with the node22 built-in runner
(`node --test tests/render-gate.test.mjs`; no package.json, no node_modules in this entry):

| Case | Property pinned |
| --- | --- |
| 1 | A healthy `out/` PASSES, with `rows_painted === rows_expected` exactly (not merely non-zero). |
| 2 | A `rows: []` board injected via `--board` makes the row FAIL — kills version (a). |
| 3 | A page that throws before first paint (the TDZ shape) FAILS with a named `page-error` **and** `row-count`, not on a byte count. |
| 4 | Static guard: the source keeps `rows_painted !== expected`, the `--board` path, the `page-error` code, and the helper travels with the gate. |
| 5 | The helper's contract: exit 2 is reserved for a browser that cannot launch; a page that throws is a RESULT (exit 0, `page_error` set). |

When the browser cannot launch, cases 1–3 report **SKIPPED with a named reason** — never a
silent pass and never a green tick over an unproven assertion.

## Screenshot band

The `screenshots` row asserts a byte window of **307,200–358,400** per screenshot, with the
recorded sizes **322,285 / 347,462 / 321,416**. The 105,432-byte collapse sits far below the
band, so a blank render fails on size as well as on row count.
